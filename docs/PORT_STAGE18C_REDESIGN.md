# PORT — Stage 18C: artwork-led launcher redesign

Дата: 2026-10-29. Локальная реализация React/Tauri по композиции предоставленного
референса, поверх Stage 18B. Тема Gemini / Liquid Glass сохранена.

## Что изменено

Главная и каталог используют один `ProjectCard`: широкий проверенный игровой кадр,
статус сборки, название проекта, описание из CMS, тип проекта, избранное и переход.
Убраны дублирующая рамка обложки, размытый фон из постера и отдельная реализация
карточки Home. Стекло осталось в навигации, фильтрах, кнопках и бейджах; изображения
не закрыты матовой панелью. Небольшая глубина hover отключается при reduced motion.

Home: оригинальная иллюстрация PORT сохранена; текст и CTA находятся прямо поверх
направленного градиента. Заголовок компактнее, уменьшены интервалы. При 1280×720
карточки начинаются примерно на Y=473 (раньше Y≈541), игровой кадр и название Sonic
видны без прокрутки. На 800×600 начало карточек также видно, горизонтального
переполнения нет.

Каталог: второстепенная панель фильтров уже, две записи образуют две ограниченные
колонки на desktop; на 800×600 — одна колонка и раскрываемые фильтры. Большой каталог
использует адаптивную сетку и существующую пагинацию. Две записи не заполняются
фиктивными проектами или пустыми колонками. Длинные названия переносятся.

Sonic: cinematic hero сохранён, на широком desktop полный игровой кадр расположен
справа от текста без чрезмерного увеличения. Слева связаны заголовок, описание,
версия, размер и кнопка. Дополнительная обложка сохранена. На небольшом окне фон
использует cover и более сильный градиент для читаемости.

Zelda: текущие кадры CMS имеют формат 4:3 и не проходят отбор для широкого hero.
Полная обложка находится рядом с компактным информационным блоком; размер панели
ограничен. Старые кадры не растянуты в фон. Галерея сразу после hero сохраняет полный
кадр через contain, просмотрщик, стрелки и Escape работают.

Downloads и Settings существенно не менялись; проверены в существующей общей теме.
Официальные ссылки, действующие версии, размеры, доступность и причины блокировки
кнопки продолжают поступать из API. Никакие данные референса не импортировались.

## Источник и правила медиа

В summary API v2 имеется только cover. Раньше Home/каталог искали скриншоты в summary
и неизбежно получали постер. Теперь существующее обогащение каталога получает detail
и builds параллельно, не более четырёх проектов одновременно. Из detail берутся
только проверенные media и описание; сборки по-прежнему проверяются существующим
builds-путём. Сбой detail не блокирует проверку сборок. Ошибка обогащения сохраняет
summary и предсказуемый fallback. Публичный контракт API и native backend не менялись.

Общий `useWideArtwork` используется в карточках и hero. Только изображения после
существующей проверки origin, immutable hash и декодирования: ширина ≥960,
высота ≥540, отношение сторон 1.5–2.4. Кандидаты ранжируются по разрешению (до 1920)
и близости к 16:9; равные сохраняют порядок CMS. Первый неподходящий кадр пропускается.
Это консервативный геометрический отбор, не семантическое распознавание и не измерение
резкости. Если подходящего кадра нет или он не декодируется — компактная portrait
строка с contain либо явное отсутствие обложки. Отдельные thumbnail и gallery
используют contain; wide card — cover. Новых ассетов, библиотек и сервисов нет.

## Проверки

- TypeScript и frontend production build проходят; прежнее предупреждение Vite
  о JS chunk >500 kB сохраняется.
- 56 целевых Playwright-проверок: API v2, доверенные медиа, ошибки, guards загрузки,
  уведомления/таймеры, история, избранное, фильтры, поиск, offline/reconnect, четыре
  языка, версии, галерея/клавиатура, titlebar, Stage 16/18B/18C.
- Новые тесты: единый отбор пропускает portrait/низкое разрешение, выбирает подходящий
  кадр и возвращается к cover fallback; 10 и 30 явно тестовых записей на трёх размерах,
  длинные названия, отсутствие overflow и переход 24→6 записей. Реальный каталог
  не меняется. Старые ожидания Stage 16 обновлены с узких постеров на широкие карточки.
- 9 Rust `hub_download` regression tests проходят: SHA-256, одобрение CMS,
  потоковая запись/отмена, no-clobber и история. Rust не редактировался.
- 18 browser before + 18 after снимков всех шести экранов на 800×600, 1280×720,
  1600×900. Одинаковые сохранённые реальные локальные CMS-ответы/арты Stage 18B;
  это browser replay, не production и не подмена данных приложения.
- Настоящий Tauri/WebView2: debug `app.port.cms-qa`, свежая отдельная папка
  `.local/stage18c/app-data`, живой локальный API v2 через существующий Rust HTTPS
  QA-транспорт. Все шесть экранов на трёх размерах, enabled CTA для двух проектов,
  gallery/Escape, maximize/restore, no WEB PREVIEW, reduced-motion и solid fallback.
  Нет JS-ошибок и horizontal overflow; список установок/история пусты. Версии API:
  Sonic v1.0.3, Zelda v1.2.2. Архивы и игры не запускались.
- Короткая проба кадров при hover в реальном WebView2 записана отдельно в
  `native-performance.json`; это только текущая машина, не универсальный GPU benchmark.
  Blur ограничен существующими поверхностями; новый полноэкранный blur не добавлен.

Снимки и воспроизводящие сценарии: [.local/evidence/stage18c/INDEX.md](../.local/evidence/stage18c/INDEX.md).
Ограничения: повторная реальная передача архива/выбор папки/OS DPI и GPU других
устройств не проверялись. Production API на Stage 18C не запрашивался; исторический
401 записан в Stage 18B. CMS-соседи, пользовательская SQLite/schema 4, Bloodborne,
legacy-данные и исходные dirty файлы не изменялись. Только локальный commit;
без push/deploy/release и без начала Stage 19.
